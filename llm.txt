# ATP Checkers — Lean 4 Formalization Error Detector

Metaprogramming-based linter detecting "Lean Semantic Traps" — code that compiles
but silently produces mathematically incorrect results. Uses **semantic guard
checking** via local facts, structural/positivity recognizers, `omega`, and
`grind` (SMT-style solver) tactics.

Release identity: `atp-checkers`. Internal Lean namespace: `AtpLinter`.

---

### Build & Test

```bash
lake build                    # Build linter and dependencies
lake build AtpLinterTest      # Run gating tests (compile-time #cov_assert_* assertions)
lake build AtpLinterDemo      # Run demo tests (non-gating, diagnostic output)

# Subprocess execution (resolves lean env once, direct invocation)
python3 -m runner datasets/examples/minimal_no_mathlib.jsonl \
  --workspace . --output out --timeout 60

# Parallel execution
python3 -m runner my_benchmark.jsonl -w . -o results -j 4

```

### Dataset Intake

The runner accepts JSONL, JSON arrays, non-recursive Lean directories, and
HuggingFace datasets:

```bash
# Canonical JSONL
python3 -m runner dataset.jsonl -w . -o out --timeout 30 -j 8

# JSON array
python3 -m runner problems.json --format json -w . -o out

# Directory containing top-level .lean files only (non-recursive)
python3 -m runner ./lean-files --format lean -w . -o out

# HuggingFace dataset
python3 -m runner AI-MO/CombiBench --format hf --split test -w . -o out

# Headerless theorem statements
python3 -m runner dataset.jsonl -w . -o out --header-file headers/mathlib.lean
```

Canonical JSONL should be one object per line:

```json
{"id":"problem_1","lean_code":"import Mathlib\n\ntheorem foo : True := by trivial","natural_language":"optional statement"}
```

Only `lean_code` is required. `id` is recommended; if absent, the loader
generates `row_<n>`. Imports are allowed in `lean_code`; do not include
`#check_atp` or `#check_atp_all`, because the runner appends the linter command.

The loader also recognizes common external schemas without pre-conversion:
- ID keys: `id`, `name`, `theorem_name`, `problem_id`, `uuid`, `theorem_names`
- Code keys: `lean_code`, `lean4_code`, `header` + `formal_statement`,
  `lean4_src_header` + `lean4_formalization`, `autoformalization`,
  `formal_statement`, `formal`
- Natural-language keys: `natural_language`, `nl_statement`,
  `informal_prefix`, `natural`, `refined_statement`, `problem`

When converting a new dataset manually, prefer canonical JSONL with stable
`id`, complete `lean_code`, and original natural-language/problem metadata
preserved as extra fields. For theorem-statement-only datasets, either prepend a
shared import/open header into each `lean_code` or pass `--header-file`.

JSON and JSONL inputs tolerate a UTF-8 BOM. Invalid rows become infra-error
result rows instead of crashing the whole batch. Duplicate problem IDs in one run
are skipped after the first occurrence.

## Confidence Model

Every finding carries `confidence` (`proven`/`maybe`) and optional `provedBy`:

```lean
inductive Confidence where
  | proven    -- Constructive proof/witness that the risky behavior occurs
  | maybe     -- Suspicious pattern, but no proof of actual failure

structure LintFinding where
  ...
  confidence : Confidence := .maybe
  provedBy : Option String := none    -- e.g. "omega", "assumption", "decide", "definitional"
```

### When `proven` vs `maybe`

| Checker | `proven` | `maybe` |
|---------|----------|---------|
| DivisionByZero (literal 0) | `isDefinitelyZero` | — |
| DivisionByZero (unguarded) | unsafety proves `d = 0` | both proofs fail |
| NatSubtraction | unsafety proves `a < b` | both proofs fail |
| ModuloByZero | unsafety proves `d = 0` | both proofs fail |
| IntToNat | unsafety proves `x < 0` | both proofs fail |
| IntDivTruncation | both literals → truncates | non-literal operands |
| Axiom, Vacuous, Counterexample | always proven | — |
| ExponentTruncation | omega proves negative exp | not proven |
| AnalyticDomain | unsafety proves violation | both proofs fail |
| UnusedBinder, ListRange, CastAfterTrunc | — | always (heuristic) |

### Unsafety Proving

When safety guard fails, checkers attempt to prove the **dangerous condition**
via `tryProveUnsafety?` using the same local-fact/prover stack:

| Checker | Unsafety goal |
|---------|--------------|
| DivisionByZero | `divisor = 0` |
| NatSubtraction | `lhs < rhs` |
| IntToNat | `intExpr < 0` |
| ModuloByZero | `divisor = 0` |
| AnalyticDomain | `x = 0` / `x < 0` / `x ≤ 0` |

### JSON Output

```json
{"category":"Potential Division by Zero","severity":"WARNING","declaration":"myDiv",
 "message":"a / b has no guard...","confidence":"proven","provedBy":"assumption",
 "taxonomyCategory":"I.d - Lean Semantic Traps"}
```

Python `Finding` maps `provedBy` (camelCase) → `proved_by` (snake_case).

## Guard Modules

The public import boundary is `SemanticGuards.lean`, but it is intentionally a
small facade. The implementation is split by concern:

- `GuardPolicy.lean`: safe local-context construction for binder-sensitive checks
- `GuardFacts.lean`: local propositions, derived structure-field facts, conjunction
  expansion, bounded forall instantiation, and standard magnitude facts
- `GuardProver.lean`: solver order and checker-facing guard queries

Layered fallback prover: `assumption`/exact local fact → positivity/structure →
`omega` → `grind`.

### Key Types

```lean
inductive ProvedBy where
  | assumption | structural | simp | byContra | omega | positivity | grind

structure LocalCtxSnapshot where
  lctx : LocalContext
  insts : LocalInstances
```

### Key Functions

```lean
def tryProve? (goal : Expr) (useOmega := true) (useGrind := false) : MetaM (Option ProvedBy)
def tryProveVacuity? (goal : Expr) : MetaM (Option ProvedBy)
def tryProveUnsafety? (goal : Expr) (snap : LocalCtxSnapshot)
  (useOmega := true) (useGrind := true) : MetaM (Option ProvedBy)
def proveDivisorSafe? (d : Expr) : MetaM (Option ProvedBy)
def proveNatSubGuard? (a b : Expr) : MetaM (Option ProvedBy)
def proveIntNonneg? (intExpr : Expr) : MetaM (Option ProvedBy)
```

### Tactic Strategy

| Domain | Chain | Rationale |
|--------|-------|-----------|
| Nat/Int guards | assumption/local facts → positivity/structure → omega → optional grind | omega handles most |
| Real/field guards | assumption/local facts → positivity/structure → optional grind | omega can't reason about Real |
| Vacuity (prove False) | assumption → omega → grind(vacuity) | Maximum power |
| Unsafety proofs | assumption → omega → grind(guard) | Same stack as guards, grind enabled by default |

Two grind configs with strict caps: `grindConfigGuard` (tight) and `grindConfigVacuity` (generous).

## Implementation Patterns

### Binder-Safe Context Policy

For theorem bodies and conclusions, guard-checking checkers open the full binder
telescope first, so independent hypotheses are available regardless of binder
order.

For binder types, the checker deliberately does not use the raw full local
context. Full context can be circular: checking `x : Fin (n - k)` while using
the later local `x` exposes `x.isLt : x.val < n - k`, which can prove the guard
only because the potentially unsafe type was already accepted. The guard policy
therefore uses a conservative "prop-full, data-prefix" context for binder types:
earlier data binders are kept, later/current data binders are dropped, and later
propositional binders are kept only when they do not depend on dropped data.

### Pre-computed Strings

Pretty-print expressions at discovery time (when binders are in scope). Store as `lhsStr`/`rhsStr`/etc. If you pretty-print after traversal, you get `_fvar.826` instead of names.

### Skip Proof Terms

Only analyze type signatures for Prop declarations. Proof terms are enormous and contain incidental operations. Non-Prop definitions do inspect the value body.

### Polarity-Aware Guard Mining

Positive conjuncts like `x ≠ 0 ∧ 1/x = x` contribute `x ≠ 0` to the guard context. Under negation or in an implication antecedent (`¬ (x ≠ 0 ∧ …)`, `(x ≠ 0 ∧ …) → True`) the same conjunct is **not** mined, so guard warnings still fire. `withExpandedAndHyps` in `GuardFacts.lean` handles this by walking only asserted prop hypotheses. See `test/GuardProvingTests.lean` → `negatedConjunctionDiv`, `antecedentConjunctionDiv`, `negatedConjunctionInv` for the gating tests.

### Deduplication

All checkers use insertion-order dedup with semantic keys (no `exprHash`):
- `HDiv.hDiv` and `Nat.div` detections merge correctly
- Deterministic output order
- Strongest-evidence-wins on collision

Key per checker: `(operandStr1, operandStr2, guardEvidence.isSome)` — varies slightly by checker.

## Runner Pipeline

The runner uses subprocess execution: it resolves the workspace Lean environment
once, invokes Lean directly per problem, and uses import-bundle caching to avoid
re-elaborating shared imports. It supports extra Lean search paths via the
`ATP_EXTRA_LEAN_PATHS` environment variable or per-problem
`metadata.extra_lean_paths`.

The runner wraps each problem's `lean_code` with `import AtpLinter` +
`#check_atp_all` and parses `ATP_LINT:` / `ATP_DONE:` sentinels from output.

**Output schema** (`results.jsonl`):
```json
{
  "schema_version": 1,
  "dataset": "...",
  "run_id": "...",
  "problem_id": "...",
  "source": "...",
  "status": "ok|findings|compile_error|timeout|infra_error",
  "findings": [{"category":"...","severity":"WARNING","declaration":"...",
                "message":"...","suggestion":"...",
                "confidence":"proven","provedBy":"omega",
                "taxonomyCategory":"I.d - Lean Semantic Traps"}],
  "error_message": null,
  "duration_ms": 1234,
  "provenance": {"lean_toolchain":"leanprover/lean4:v4.30.0-rc2","timestamp":"..."},
  "compile_error": false,
  "compile_error_message": null,
  "metadata": {"natural_language":"...", "...":"..."}
}
```

Rows can have `status = "findings"` and `compile_error = true` simultaneously
when the linter emitted findings despite unrelated compile errors in the file.

**Note:** Problems with `import Mathlib` require a pre-built Mathlib in the workspace. Use `minimal_no_mathlib.jsonl` for self-contained smoke tests.

## Change Policy

When editing checker behavior:
1. Update checker code in `src/AtpLinter/`
2. Add/adjust tests in `test/`
3. Validate runner output shape if JSON fields change
4. Update `README.md` and `datasets/FORMATS.md` if user-facing contracts change

Confidence contract (`confidence`: `proven` | `maybe`, `provedBy`: string or null) should remain stable.

Prompt sets and prompt pipelines live outside this repository.

## Limitations

1. **Mathlib**: Required as dependency for full benchmark analysis; must be pre-built in workspace
2. **Grind scope**: Extends to ordered rings/fields (Real) but may need `@[grind]` annotations for some lemmas
3. **Complex guards**: May miss guards behind definitions or type class instances
4. **omega off for Real**: omega disabled for Real types; relies on grind for field reasoning
